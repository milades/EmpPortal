# راهنمای فاز ۲: فرم‌ساز داخلی

## دامنه تحویل

فاز ۲ یک فرم‌ساز فارسی و راست‌چین در Blazor Interactive Server ارائه می‌کند. مدیر می‌تواند فرم را
بسازد، با Drag & Drop یا دکمه‌های جابه‌جایی مرتب کند، پیش‌نمایش ببیند، ذخیره و نسخه منتشر کند،
زمان باز و بسته‌شدن تعیین کند، آن را متوقف/فعال/بایگانی کند و دسترسی را برای همه، نقش یا کاربر مشخص
تعریف کند. کاربران فرم منتشرشده را تکمیل یا به‌صورت پیش‌نویس ذخیره می‌کنند و مدیر پاسخ‌ها را در پرتال
می‌بیند و Excel یا PDF دریافت می‌کند.

Workflow تأیید، آپلود فایل، امضای دستی و نمودارهای آماری طبق تصمیم محصول در این فاز نیستند. ساختار
نسخه‌بندی و شناسه Submission برای افزودن این قابلیت‌ها در فازهای بعد حفظ شده است.

## مسیرهای پرتال

| مسیر | کاربرد | نقش/مجوز |
|---|---|---|
| `/forms` | فهرست فرم‌های قابل استفاده | کاربر احراز‌شده و ACL فرم |
| `/forms/{slug}` | تکمیل، پیش‌نویس و ثبت نهایی | `View` و `Submit` |
| `/admin/forms` | ساخت و مدیریت فرم | نقش مدیریتی فرم |
| `/admin/forms/{id}/builder` | طراح، تنظیمات، ACL، نسخه و پیش‌نمایش | `Manage`؛ انتشار نقش جدا دارد |
| `/admin/forms/{id}/submissions` | گزارش جدولی و Excel | `ViewSubmissions`/`Export` |
| `/admin/submissions/{id}` | جزئیات، چاپ مرورگر و PDF | `ViewSubmissions`/`Export` |

نقش‌های SQL این ماژول عبارت‌اند از `FormAdministrator`، `FormDesigner`، `FormPublisher`،
`SubmissionViewer` و `ReportExporter`. `SystemAdministrator` همه دسترسی‌ها را دارد. مالک فرم نیز
در ACL خود فرم دسترسی کامل می‌گیرد. نقش‌ها هنگام ورود موفق از مسیر استاندارد Microsoft Identity
همگام می‌شوند و مجوز واقعی دوباره در سرویس سمت سرور کنترل می‌شود؛ مخفی‌کردن دکمه در UI مرز امنیتی نیست.

## المنت‌ها و رفتار فرم

انواع متنی، متن چندخطی، متن غنی امن، عدد، مبلغ، درصد، ایمیل، تلفن، URL، کد ملی، تاریخ، تاریخ‌وزمان،
زمان، بازه تاریخ، Select، MultiSelect، Radio، Checkbox، Switch، Slider، Hidden، کاربر جاری، مقدار
محاسباتی، Heading، Paragraph، Divider، Alert، Repeater و Table پشتیبانی می‌شوند.

- اعتبارسنجی طول، بازه عددی، Regex با timeout، گزینه‌های مجاز، ردیف‌های تکرارشونده و پیام سفارشی
  هم در UI و هم در Application اجرا می‌شود.
- شرط نمایش از DSL داده‌ای محدود استفاده می‌کند؛ عبارت محاسباتی فقط عملگرهای عددی و توابع مجاز را
  می‌پذیرد. `eval`، JavaScript، SQL یا C# دلخواه اجرا نمی‌شود.
- RichText در این فاز متن قالب‌بندی‌شده امن است و HTML خام مدیر/کاربر Render نمی‌شود تا XSS وارد
  مرز اعتماد نشود.
- مقدار CurrentUser و فیلدهای محاسباتی در سمت سرور بازتولید می‌شوند؛ مقدار ارسالی مرورگر قابل اعتماد نیست.
- دکمه‌ها، binding و eventها در فرم‌ساز/فرم کاربر با Interactive Server پیاده شده‌اند؛ صفحات Account
  همچنان Static SSR و مبتنی بر POST استاندارد باقی مانده‌اند.

## چرخه عمر، زمان‌بندی و نسخه‌ها

وضعیت‌ها `Draft`، `Published`، `Paused` و `Archived` هستند. فرم منتشرشده تنها در بازه UTC تنظیم‌شده
قابل مشاهده/ارسال است. هر انتشار، نسخه Draft موجود را immutable می‌کند و Draft بعدی را از روی آن
می‌سازد. هر پاسخ به `FormVersionId` دقیق متصل است؛ بنابراین تغییر بعدی فرم، مشاهده و PDF پاسخ قبلی
را خراب نمی‌کند. ویرایش هم‌زمان مدیر یا کاربر با SQL `rowversion` تشخیص داده می‌شود.

حذف فیزیکی فقط وقتی نمایش داده و در سرویس مجاز می‌شود که فرم در وضعیت Draft باشد، هرگز منتشر نشده
باشد و هیچ پاسخ نهایی یا پیش‌نویس کاربری نداشته باشد. حذف دائمی با SweetAlert2 تأیید می‌شود، همه
شرط‌ها داخل تراکنش سمت سرور دوباره کنترل می‌شوند و رخداد حذف در Audit باقی می‌ماند؛ در سایر وضعیت‌ها
راه درست، بایگانی فرم است.

## ذخیره‌سازی و گزارش

جداول ماژول در schema دیتابیس `forms` قرار دارند. تعریف نسخه و payload پاسخ به‌صورت JSON نگه‌داری
می‌شود و پاسخ‌های نهایی هم‌زمان در `FormAnswerIndexes` به ستون‌های متنی، عددی و زمانی index می‌شوند.
این طراحی نسخه‌پذیری فرم را با گزارش‌گیری SQL متعادل می‌کند؛ جزئیات تصمیم در
`docs/architecture/adr/0005-dynamic-form-storage-and-versioning.md` آمده است.

Excel حداکثر ۵۰٬۰۰۰ پاسخ در هر خروجی می‌سازد و مقدارهای متنی مستعد Formula Injection را خنثی می‌کند.
برای حجم بیشتر باید بازه گزارش محدود یا در فاز بعد Job غیرهم‌زمان اضافه شود. PDF از فونت محلی
Vazirmatn استفاده می‌کند و به اینترنت نیاز ندارد.

## تنظیم PDF در محیط عملیاتی

نوع مجوز QuestPDF باید پیش از Production توسط واحد حقوقی/تدارکات تعیین شود. `Community` فقط در صورت
احراز شرایط رسمی آن مجاز است؛ سازمان‌های غیرواجدشرایط باید `Professional` یا `Enterprise` تهیه کنند.
برنامه در محیط غیر Development با `Evaluation` یا مقدار خالی Fail-fast می‌شود. در
`appsettings.Production.json` کنار فایل برنامه قرار دهید:

```json
{
  "Forms": {
    "Pdf": {
      "License": "Professional",
      "RegularFontPath": "wwwroot/fonts/Vazirmatn-Regular.ttf",
      "BoldFontPath": "wwwroot/fonts/Vazirmatn-Bold.ttf"
    }
  }
}
```

مقدار نمونه را با `Community`، `Professional` یا `Enterprise` واجدشرایط جایگزین کنید. این تنظیم
restart-required و عمداً خارج از پنل
Runtime است، چون یک اعلام حقوقی/عملیاتی است نه تنظیم روزمره محصول.

## Migration و آزمون پذیرش

Migration این فاز `20260804090939_AddDynamicFormsPhaseTwo` است. در عملیات، ابتدا Backup و سپس
`deploy/sql/EmpPortal.Migrations.sql` با حساب Migration اجرا و بعد
`deploy/sql/EmpPortal.RuntimePermissions.sql` برای حساب Runtime اعمال می‌شود.

Smoke Test حداقلی:

1. ورود مدیر و ایجاد فرم با فیلد اجباری، شرط، گزینه و فیلد محاسباتی.
2. ذخیره Draft، انتشار، بررسی نمایش در `/forms` و رعایت زمان‌بندی/ACL.
3. ذخیره پیش‌نویس کاربر، ادامه همان پاسخ و ثبت نهایی.
4. مشاهده پاسخ با نقش گزارش، دانلود Excel و PDF و چاپ صفحه.
5. توقف و ادامه فرم، انتشار نسخه دوم و تأیید اینکه پاسخ نسخه اول همچنان خوانا است.
6. آزمون عدم دسترسی کاربر/نقش خارج از ACL و عدم دسترسی `SubmissionViewer` به انتشار.

زمان‌های دیتابیس UTC هستند. Time zone ویندوز سرور باید توسط عملیات تعیین و نمایش ساعت در UAT با
`Iran Standard Time` کنترل شود. Backup/Restore، ظرفیت concurrent Blazor circuits و خروجی‌های حجیم
باید با داده و زیرساخت واقعی سازمان تست شوند.
